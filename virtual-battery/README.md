# 虚拟电池情景求解服务（FastAPI + Vue）

不连接任何真实电力设备。服务保存电池情景及其修订号，按三级优先级求最优充放电计划，
并提供逐段电量、购电与弃光证据；前端编辑时立即让旧计划作废，并以乐观修订号防止并发覆盖。

## 模型

每份情景含 8～48 个时段，逐段为整数：用电量 `load`、光伏发电 `pv`、购电单价 `price`；
电池参数：容量（≤50）、初始电量、终点最低电量、每段最大充电量、每段最大放电量。

逐段规则：

- 电量守恒：`期初电量 + 购电 + 光伏消纳 = 用电 + 期末电量`；
- 同一段不允许既充又放（动作 `a_t`：正=充电量，负=放电量，0=静置）；
- 放电不得超过净负载 `load - pv`（不能借光伏放电、不能售电）；
- 购电量始终非负；光伏超过负荷的部分计入**弃光**，可弃不可售；
- 所有量均为整数。

目标按字典序：

1. 总购电费用 `Σ price·buy` 最小；
2. 总购电量 `Σ buy` 最小；
3. 仍并列时充放电动作序列 `[a_0 … a_{T-1}]` 字典序最小（充电为正、放电为负，故尽量静置、其次放电）。

求解器为**向后动态规划**（整数电量，状态数 ≤ 48×51），不依赖外部 MILP；
并列项的字典序由“动作升序扫描 + 前向重构时取最小可行动作”得到。

## 修订号与旧计划防护

- `POST /api/scenarios` 新建，修订号从 1 开始；
- `PUT /api/scenarios/{id}?expected_revision=n` 仅当 `n` 等于当前修订号时覆盖并自增，
  否则返回 **409**（响应体给出当前修订号），拒绝静默覆盖；
- `POST /api/scenarios/{id}/solve?expected_revision=n` 只求解该修订号；情景已被别人保存为
  更新修订号时返回 **409**，旧求解响应不会被当成新情景的计划；
- 前端在任何字段被编辑时立即把页面计划标记为过期（半隐 + 警示），保存/重载后清除计划，
  必须对新修订号重新求解。

## 返回证据

每段返回：动作、充/放电量、期初/期末电量、购电量、单价、费用、光伏、光伏消纳、弃光、
净负载，以及守恒等式两端 `balance_lhs / balance_rhs` 供核对。

## 运行

```bash
pip install fastapi "uvicorn[standard]"
cd virtual-battery
python3 -m uvicorn app.main:app --reload
# 浏览器打开 http://127.0.0.1:8000/
```

前端为 Vue 3 全局构建（已随仓库放在 `static/vue.global.prod.js`，无需联网、无构建步骤）。

## 测试

```bash
pip install pytest httpx
cd virtual-battery
python3 -m pytest
```

- `tests/test_solver.py`：短时段随机情景下**穷举所有合法动作**（独立的递归实现）
  与 DP 对拍，校验三级目标、动作字典序、逐段守恒、不售电与弃光账目；
- `tests/test_api.py`：修订号生命周期、8 线程并发同号保存（恰 1 成功、7 个 409）、
  编辑后旧修订号求解 409、输入校验、API 结果与穷举一致。
